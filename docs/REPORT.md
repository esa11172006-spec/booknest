Лабораторная работа №2. Адаптивная вёрстка и дизайн-токены
1. Система дизайн-токенов
Вся стилизация построена на CSS-переменных, которые хранятся в файле styles/tokens.css. Это позволило избежать «магических» значений в компонентах.
Реализовано более 14 переменных, разделенных на категории:

Цвета: --color-bg, --color-surface, --color-text, --color-primary и др.

Отступы: шкала от --space-1 (4px) до --space-6 (48px).

Радиусы: --radius-sm, --radius-md, --radius-lg.

Типографика: --font-base, --fs-sm, --fs-base, --fs-lg, адаптивный --fs-xl через clamp().

2. Адаптивность и сетки
Вёрстка выполнена по принципу Mobile-first.

Шапка реализована на Flexbox с flex-wrap: wrap, благодаря чему навигация корректно переносится на узких экранах.

Каталог построен на CSS Grid: grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));. Это позволяет сетке автоматически перестраиваться от 1 колонки на мобильных до 3-4 на десктопе без использования media queries.

Прижатый футер: реализован через flex на body и flex: 1 у основного контента.

3. Тёмная тема
Тёмная тема реализована через @media (prefers-color-scheme: dark) исключительно в файле токенов. Компоненты не дублируются, так как они используют семантические переменные.

4. Доступность и состояния
Для всех интерактивных элементов настроен :focus-visible с ярким контуром.

Учтены состояния :invalid и :disabled для форм.

Добавлена поддержка prefers-reduced-motion для отключения анимаций.

Лабораторная работа №3. JavaScript-приложение: каталог с фильтрами
1. Архитектура приложения
Приложение написано на чистом JavaScript (ESM-модули) с разделением ответственности:

data/books.js — локальная база данных (40 книг, 5 жанров).

lib/books.js — чистые функции (фильтрация, сортировка).

ui/render.js — модуль отрисовки DOM (не знает о бизнес-логике).

main.js — единый объект state, обработчики событий и функция update().

2. Чистые функции (lib/)
Функции filterBooks, sortBooks и getVisibleBooks не мутируют входные данные и не обращаются к DOM.
Важно: в функции сортировки используется копия массива [...books], чтобы не изменить исходный порядок книг в базе.

3. Управление состоянием (State)
В main.js реализован ровно один объект state, который хранит:

текущий поисковый запрос,

выбранный жанр,

режим сортировки,

чекбокс доступности,

массив ID книг в «Моем списке».
Любое действие пользователя (ввод текста, клик) обновляет state и вызывает единую функцию update(), которая перерисовывает интерфейс. Интерфейс всегда является функцией состояния.

4. Делегирование событий
Обработчик кликов навешан только на document. С помощью e.target.closest('[data-action="toggle-wishlist"]') мы определяем, какая именно кнопка была нажата. Это решает проблему потери слушателей при перерисовке карточек.

5. Безопасность и LocalStorage
Ввод пользователя и данные книг выводятся исключительно через textContent (защита от XSS).

Сохранение состояния в localStorage обернуто в блок try/catch и защищено проверками типов, чтобы приложение не упало при испорченных данных.

Код успешно проходит проверку ESLint без ошибок и предупреждений.
